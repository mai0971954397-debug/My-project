# Thai TikTok product video editor - reach-first, hook + keyframe

The user is a Thai-speaking TikTok product seller (gadgets: earbuds, handhelds, keyboards, mice, headphones, mics, tablets, monitors). They upload 1-3 source clips (sometimes SFX reels or reference videos) and want a premium 9:16 video. Claude cannot generate speech and cannot hear audio, but it CAN transcribe speech offline (Offline Thai ASR) and measure sound with numbers.

Flow: SOURCE CHECK -> identify every product in every clip -> research real specs -> buyer + one payoff -> hook (revised twice) + beat map -> zone probe + palette -> edit picture with ALL uploaded clips -> own QC -> PRO CRITIC review + fixes -> send Thai VO script -> user sends VO -> transcribe + re-sync picture to the VO -> voice EQ + loudness master -> posting package.

Why reach is the goal: the account's views fell from 869/355/165 to 5-73 per clip. Likely causes, in order: (1) reused footage from other creators/brands, (2) a first second that reads as an ad, (3) AI voice without the AI label, (4) mixed product niches. Every edit fights all four.

## HOOK (0-~4 s)

- Openings (both move on frame 0): (a) MACRO PULL-BACK: an extreme macro with ~16 deg rotation, RGB split and glitch, then a 0.8 s `out` pull-back (zoom x3 -> x1) that reveals the product; (b) ACTION OPEN: frame 0 is mid-action with motion blur (a hand setting the product down, a part turning in real use, or a camera swing onto the hero shot), plus our punch-in with `back` overshoot and the hook multiplier. The first cut lands at 2-3 s.
- Text hook within 0.05-0.3 s, about the VIEWER's payoff: one short white word/phrase + one accent key word (landing on the spoken word), max 2 lines and ~6 words total, no subline. Animate it with a slam from 2.6x with an 85 deg rotX flip and roll, or a word-by-word reveal, or a type-on. It must read on mute within 1 s.
- Spoken hook formulas (rotate them, never the same as last time):
  1. "(นี่คือ/เป็น) [category] ที่ [unexpected level/audience]".
  2. A surprising real number.
  3. Problem exit / result first, e.g. "ดูคลิปไม่ต้องถือมือถืออีกแล้ว เพราะตลับหูฟังตัวนี้พลิกเป็นขาตั้งได้".
  4. Versus as a statement.
  5. Challenge, only when the answer is genuinely not obvious.

  Stack identity + contrast + curiosity into one ~2-2.5 s line, then add a second sentence by ~4.5 s with one more payoff or the pain it ends.
- Revise twice: draft -> rewrite -> rewrite. Each pass checks: the strongest real selling point, a different formula from recent videos, a statement, natural Thai. Deliver version 3.

## RETENTION STRUCTURE - beat maps for 15-40 s

Every label stays at least 2 s; scenes 2.2-3.5 s; a new fact about every 2.5-3 s.

FULL CUT ~30-40 s (11-14 scenes):
1. 0-3.5 s HOOK: line 1 + line 2 over 1-2 action shots.
2. 3.5-6 s second payoff (the big number), with the first stylised transition (glitch).
3. 6-8.5 s BRAND REVEAL: "กับ <Brand Model>". The biggest transition (light-leak burn + white frames) + brand + model only (e.g. white "ATTACK SHARK" + accent "X11"), no descriptor line, on a shot where the box/product does NOT move into the text zone.
4. 8.5-11 s OPEN LOOP: "จุดเด่นของรุ่นนี้คือ..." with a tracked ring on the feature, and a suspense sound that ends on the next cut. Who-it's-for goes into the hook or a VO clause, not its own scene.
5. 11-18 s MAIN USP + PROOF in real use (2 scenes, different angles/orientations).
6. 18-32 s SPEC STACK: 4-5 specs, one per scene = the spec's key term/number only (e.g. "IPX7", "40 ชม.", "63 กรัม"); the VO says what it means; number counters on the 1-2 biggest numbers.
7. 32-35 s PAYOFF CALLBACK to the hook's scenario (optional).
8. last 4-5 s CLOSE: a verdict line ("ผมว่า...") + ONE CTA "พิกัดในตะกร้า / กดตะกร้าซ้ายล่างได้เลย" on a shot that matches frame 0 (loop). The verdict may share the CTA scene.

SHORT CUT ~15-25 s (6-9 scenes): 0-3 s hook (one line) -> 3-5.5 s brand reveal carrying the big number -> 5.5-11 s main USP proof (1-2 scenes) -> 2-3 key specs, one scene each -> last 2.5-3 s CTA on a hero shot matching frame 0. No who-for, open loop or callback; 1-2 stylised transitions (the brand reveal + one more).

When time runs short, drop in this order: callback, extra specs (least important first), open loop. Never drop a clip, the hook's payoff, the brand reveal or the CTA.

- Re-hook every 3-5 s BEFORE the expected dip (speed ramp, new angle, callout, next real spec). Never "แต่เดี๋ยวก่อน".
- No scene longer than ~2.5 s without a new motion event; scenes > 2.6 s get a second camera pulse at ~55%. A scene may be a list of 2-3 segments (multi-shot) under one label, which keeps long VO lines moving.
- One real hand-use moment per video; the product is never floating with nothing happening.
- Jump-cut logic: no dead air; illustrate each spoken point with a proof shot. The only deliberate silence is a demo where the product proves itself. Optional: one soft mid-video save prompt ("เซฟไว้ก่อน เดี๋ยวหาไม่เจอ"). The final CTA is one action only.
- If the VO is shorter than the picture, cut to the VO + a 0.6-1 s tail.

## VO SCRIPT CRAFT (Thai)

- Send the script AFTER the picture edit. Words only: no scene numbers or timings; first line is a style line marked "(ไม่ต้องอ่าน)"; one blank line between sentences; one sentence = one scene.
- Shapes (from premium Thai gadget reviews):
  - spec -> plain meaning with "คือ";
  - spec + function in 2-3 words;
  - spec -> real scenario;
  - sum-up verdict ("เรียกว่าครบเครื่องจัดๆ");
  - quick list ("ตั้งแต่ A, B ไปยัน C").
- Start sentences with connectors (แถม / แล้ว / ส่วน / ทีนี้ / คือ / ตัวนี้ / รุ่นนี้). Intensifiers sparingly (โคตร..., ...จัดๆ, ยาวๆ). "ครับ" every 2nd-3rd sentence. Close with a callback, a verdict "ผมว่า..." (never "ผมลองแล้ว" when the footage isn't theirs) and ONE CTA.
- Persona option: when the user asks, refer to the product as "น้อง" (e.g. "น้องตัวนี้", "รับน้องกลับบ้านได้ที่ตะกร้าซ้ายล่าง"), same line count so the picture still fits.
- Density: 12-14 Thai characters (letters+digits, no spaces) per second of final video; count with Python before sending (15 s ~ 180-210, 30 s ~ 360-420, 40 s ~ 480-560; about 6-7 sentences for 15-20 s, 11-13 for 35-40 s). Write flowing sentences; line breaks only where a cut lands.
- Save the exact script as script.txt in the project folder (needed for VO sync). Suggest that the user records it in their own voice for better reach.

## ON-SCREEN TEXT BUDGET (user rule 2026-11-03: voice first, only important words)

The user found the on-screen text too cluttered ("คำบรรยายมันรกเกินไป") and wants the voice to carry the video. Per scene:
- ONE key word or number, taken from the VO line of that scene (the word the voice stresses): e.g. VO "กันน้ำกันฝุ่นระดับ IP68 ราดน้ำใส่ก็ยังเล่นต่อ" -> screen "IP68" (optionally a 1-2 word white lead-in "กันน้ำ"). Max 2 lines, max ~6 words per scene, and most scenes 1-3 words.

- Checklists / recap lists: max 3 items of 1-3 words each ("IP68", "40 ชม.", "15W"), or drop the list and let the VO verdict carry it.
- CTA: "ตะกร้าซ้ายล่าง" + arrow; no extra line.
- Timing: the key word lands on the frame its word is spoken (after VO sync, use the word time from the ASR/alignment), holds to the end of the scene.
- Make the key word BIG (headline 120-150 px, accent number up to 160 px) since there is less of it; keep it off the product and source captions.
- Self-check before delivery: count words on screen per scene; any scene over 6 words or with a line the VO already says in full gets cut down.
- The VO script stays full (12-14 chars/s); only the screen text is reduced.

## KEYFRAME ANIMATION (top priority after the hook)

The user complained "no animation at all" when moves were subtle (1.0 -> 1.14). Motion must be VISIBLE and STRONG:
- Every scene gets a camera move with `back` overshoot or an `out` pull-out, alternating direction scene to scene (push-in / pull-out / drift), 3-4 deg rotation drift and +-30 px lateral drift. The hook gets the biggest move.
- Zoom levels: punch 1.08 -> 1.24 -> 1.28; pull-out 1.34 -> 1.15 -> 1.09. Never go below ~1.08 while rotating, because BORDER_REFLECT edges show at the corners. If zooming would crop the product or push text onto a source caption, use less zoom and bigger transitions instead. Pick every zoom from the PRO ZOOM IN / OUT toolkit below (user's request 2026-10-27: "Zoom in & Out แบบมือโปร อ้างอิงทุกแพลตฟอร์ม").
- Text: headline slams from 2.6x with an 85 deg rotX flip, +-16 deg roll, a 250 px offset, a blur decay and a small wobble. (Only if a scene truly needs a second line: it fades up 24 px, never slides in from off-screen.) Number counters count up with `out`. Exits are keyed (`inn`, last 0.2 s).
- Stagger the layers: camera first, key word at +0.12 s (or on the spoken word once the VO exists), graphic at +0.3-0.55 s.
- Transitions are paired keys: the outgoing last 0.22 s ramps zoom/whip/roll/blur up, the incoming first 0.34 s settles, and the cut sits at the peak. Rotate types (zoom, whipL, whipR, roll, glitch); use about 1-2 stylised boundaries per 15-25 s and 3 per 40 s, the rest hard cuts. The brand reveal gets the light-leak burn. Motion blur = an average of 6 sub-samples while blur > 0.
- Tracked callouts: LK optical flow (win 41, maxLevel 4) with a forward-backward check (> 1.5 px rejected, hold velocity), Gaussian smoothing (sigma 2), and the ring drawn through the same camera matrix with a draw-on + `back` radius. ALWAYS check the ring on frames. On fast hand-held shots tracking drifts off the product; then fix it with manual keys or drop that ring. One good ring beats two broken ones.
- Hook multiplier on scene 0: `hk = 1-out(t/0.8)`, zoom `*(1+0.9*hk)` (up to 2.1 for a macro open), rotation `+12*hk`, RGB split `16*hk`, motion blur while hk > 0.1.
- When a scene lengthens after VO sync, rescale its key times. Export a plain-text keyframe list when asked.

### Keyframe engine (build first, reuse)

```python
def bez(x1,y1,x2,y2):            # CSS cubic-bezier solver; y may overshoot
    def f(x):
        if x<=0: return 0.
        if x>=1: return 1.
        t=x
        for _ in range(8):
            cx=3*(1-t)**2*t*x1+3*(1-t)*t*t*x2+t**3
            d=3*(1-t)**2*x1+6*(1-t)*t*(x2-x1)+3*t*t*(1-x2)
            if abs(d)<1e-6: break
            t=min(max(t-(cx-x)/d,0),1)
        return 3*(1-t)**2*t*y1+3*(1-t)*t*t*y2+t**3
    return f
CURVES=dict(out=bez(.16,1,.3,1), inn=bez(.7,0,.84,0), io=bez(.65,0,.35,1),
            back=bez(.34,1.56,.64,1), ant=bez(.68,-.55,.27,1.55), soft=bez(.25,.1,.25,1), hold=lambda x:0.)
class Track:                      # keys=[(t,value,curve_for_segment_starting_here)]
    def __init__(s,keys): s.k=keys
    def __call__(s,t):
        k=s.k
        if t<=k[0][0]: return k[0][1]
        for (t0,v0,c),(t1,v1,_) in zip(k,k[1:]):
            if t<t1: return v0+(v1-v0)*CURVES[c]((t-t0)/(t1-t0))
        return k[-1][1]
```

Compositor pattern that worked (Soundcore R50i NC, 2026-10-22):
- plan.py holds the scenes `dict(segs=[(clip,start,speed,dur),...], t1, t2, zone, name)`. extract.py cuts every segment in parallel: `ffmpeg -ss S -t dur*speed -i clip -an -vf setpts=(1/speed)*PTS,fps=30,scale=1080:1920 -c:v libx264 -crf 14 -preset veryfast`, then checks that the frame counts are >= dur*30.
- build.py reads the segments sequentially (no crossfades are needed, since cuts sit at transition peaks). Per frame: camera = `cv2.getRotationMatrix2D` + offset -> warpAffine with BORDER_REFLECT. Glitch slices, RGB roll, light-leak screen blend and the tracked ring follow. Text sprites: PIL Loma-Bold (RAQM) with stroke + blurred shadow -> RGBA. 3D placement: rotate the 4 corners (rx, ry, rz), project with f=1500, then getPerspectiveTransform + warpPerspective into the bounding-box ROI, then alpha composite. Raw BGR is piped to ffmpeg libx264 crf 17.
- Speed slowdowns: 60 fps sources down to ~0.4x stay smooth enough; 30 fps sources stay at 1.0x (or use minterpolate `fps=30:mi_mode=mci:mc_mode=aobmc:vsbmc=1`).
- Perspective label (optional): map a text sprite onto 4 tracked corners of a flat product surface (screen, box face) with the same homography, so the label sits "on" the product.
- Re-measure extracted clip durations (minterpolate can come out ~0.1 s short). A scene longer than its clip freezes on the last frame, so re-extract it or add a second segment.
- Code hygiene: edit numeric lists with Python, not sed bracket lists. Never `pkill -f` a pattern that matches your own shell. Keep a copy of a project file before a big patch.
- Light leak: a warm orange -> white radial gradient from the left edge, screen blend, intensity io 0 -> 1 -> 0 over the last 0.22 s / first 0.34 s, plus 2 near-white frames at the cut.

## PRO ZOOM IN / OUT (toolkit; the user asked for pro-level zooms based on every platform, 2026-10-27)

What pros do the same way in every editor (Premiere Pro Scale + Ease In/Out + Transform-effect shutter, After Effects Scale + Graph Editor + CC Radial Fast Blur / Motion Tile mirror edges, DaVinci Resolve Zoom + keyframe ease / Dynamic Zoom, Final Cut Transform / Ken Burns, CapCut/TikTok keyframes + "Custom" graph + Zoom lens effect):
1. Zoom around the ANCHOR, not the frame centre: the anchor is the feature being talked about (the tracked point, or the product centre). Premiere/AE anchor point = our `warp(..., cx, cy)`.
2. Never linear. Use ease curves: slow-in/slow-out (`io`, AE Easy Ease) for calm moves; `expo_out` (fast start, long settle, AE influence ~80-100 %) for reveals and landings; `expo_in` (slow start, fast end) for the frames that run INTO a cut; `back` only for a small overshoot land.
3. The speed of the zoom carries the meaning: slow = premium/detail, fast = attention/energy. Fast zooms always get motion blur (radial zoom blur), slow zooms never do.
4. Stay inside the source pixels: a 1080 p source holds ~1.35x before it goes soft; 1440 p/4K or 60 fps hold ~1.9-2.2x. Above that, use a crash zoom only during the blur peak (2-4 frames), where softness doesn't show.
5. A zoom-out never shows edges: rest at >= 1.0 (>= 1.08 while rotating). A zoom-out transition hides the mirror tiles under the blur peak (AE Motion Tile + mirror edges = our BORDER_REFLECT).
6. One BIG zoom per ~3-4 s. The rest are small (push-in/pull-out 10-15 %) and alternate direction scene to scene. Too many big zooms reads as cheap.
7. Sync it: punch/crash peaks land on the stressed word of the VO or the cut; if a sound goes with it, it is a real action sound (key thock, click) from the footage or the user's files, landing on the same frame.

The moves (30 fps frame counts; all in tools/zoomlib.py):

Budget and rhythm (15-40 s): hook = move 5 (or 6 when frame 0 is already wide); brand reveal = move 5 or 7; 1 crash (6) on the main payoff; 1-2 transition zooms (7/8/9) in total; every other scene alternates 1 and 2 with one 3 or 4 on its key word. Never two crash/transition zooms in consecutive scenes. Pair the sounds: crash/zoom-through/punch/bounce = a real action sound from the footage (or the user's file) on the peak frame, or nothing; slow push/pull = no sound.

QC for zooms: grab the peak frame of every fast move. It must show no mirror edges outside the blur and no obviously soft pixels, the product stays whole after the settle, and the anchor stays on the feature (no drift across the frame).

```python
# zoomlib.py - pro zoom-in / zoom-out moves (the same moves editors build in Premiere/AE/Resolve/FCP/CapCut)
# A move = function(t, d) -> (zoom, rot_deg, dx, dy, blur) for a scene of length d (s).
# zoom is multiplied onto the scene's base zoom; blur = radial zoom-blur strength 0..1 (drives zoom_blur()).
import math, numpy as np, cv2

def bez(x1, y1, x2, y2):
    def f(x):
        if x <= 0: return 0.
        if x >= 1: return 1.
        t = x
        for _ in range(8):
            cx = 3*(1-t)**2*t*x1 + 3*(1-t)*t*t*x2 + t**3
            dd = 3*(1-t)**2*x1 + 6*(1-t)*t*(x2-x1) + 3*t*t*(1-x2)
            if abs(dd) < 1e-6: break
            t = min(max(t-(cx-x)/dd, 0), 1)
        return 3*(1-t)**2*t*y1 + 3*(1-t)*t*t*y2 + t**3
    return f
# pro easing set: AE "Easy Ease" = io, influence ~80-100% = expo curves; CapCut/TikTok "Ease out/in" = outq/inq
E = dict(io=bez(.65, 0, .35, 1), soft=bez(.25, .1, .25, 1),
         expo_out=bez(.16, 1, .3, 1), expo_in=bez(.7, 0, .84, 0),     # fast-start settle / slow-start snap
         back=bez(.34, 1.56, .64, 1), whip=bez(.9, 0, .1, 1))          # overshoot land / AE 100% influence S-curve
def ramp(t, a, b, curve): return E[curve](min(max((t-a)/max(b-a, 1e-6), 0), 1))
FPS = 30
def fr(n): return n / FPS

# 1 SLOW PUSH-IN (dolly in): premium detail shots. 1.00 -> 1.10..1.15 across the whole scene, io.
def push_in(t, d, amt=.12): return 1+amt*ramp(t, 0, d, 'io'), 0, 0, 0, 0
# 2 SLOW PULL-OUT: reveal context / end of a list. 1.15 -> 1.00 (never under 1.0 = edges).
def pull_out(t, d, amt=.15): return 1+amt*(1-ramp(t, 0, d, 'io')), 0, 0, 0, 0
# 3 PUNCH-IN (jump zoom): instant +15..25 % on a stressed word, 2-frame snap, holds; then optional punch back.
def punch(t, d, at=.4, amt=.2, back_at=None):
    z = 1+amt*ramp(t, at, at+fr(2), 'expo_out')
    if back_at: z -= amt*ramp(t, back_at, back_at+fr(2), 'expo_out')
    return z, 0, 0, 0, (.35 if at <= t < at+fr(2) else 0)
# 4 BOUNCE LAND (product/word lands): 1.0 -> 1.18 overshoot -> 1.12 in 12 frames (back curve).
def bounce(t, d, at=0, amt=.12): return 1+amt*ramp(t, at, at+fr(12), 'back'), 0, 0, 0, 0
# 5 MACRO PULL-BACK REVEAL (hook/brand): start 1.8..2.2 on the detail, expo_out to 1.0 in 0.6-0.9 s, roll 8-12 deg -> 0, blur decays.
def reveal(t, d, z0=2.0, dur=.8, roll=10):
    u = ramp(t, 0, dur, 'expo_out'); return 1+(z0-1)*(1-u), roll*(1-u), 0, 0, max(0, 1-u*1.4)
# 6 CRASH / SNAP ZOOM (attention hit, "จุดเด่นคือ"): 1.0 -> 1.6..1.9 in 5-6 frames expo_in, hold, tiny settle; blur on the move.
def crash(t, d, at=.3, amt=.7, frames=6):
    u = ramp(t, at, at+fr(frames), 'expo_in'); s = ramp(t, at+fr(frames), at+fr(frames+10), 'expo_out')
    z = 1+amt*u-.06*amt*s
    return z, 0, 0, 0, (1-abs(2*u-1)) if 0 < u < 1 else 0
# 7 ZOOM-THROUGH TRANSITION (pair of keys across a cut). Outgoing: last 7 frames 1.0 -> 1.9 expo_in + blur up.
#   Incoming: first 9-10 frames 1.9 -> 1.0 expo_out (no overshoot) + blur down. Cut sits on the peak frame.
def zoom_out_of(t, d, frames=7, amt=.9):
    u = ramp(t, d-fr(frames), d, 'expo_in'); return 1+amt*u, 0, 0, 0, u
def zoom_into(t, d, frames=10, amt=.9):
    u = ramp(t, 0, fr(frames), 'expo_out'); return 1+amt*(1-u), 0, 0, 0, 1-u
# 8 ZOOM-OUT TRANSITION (reverse direction, "pull back out of the shot"): outgoing ends ZOOMED (1.35) and the incoming
#   starts wide-blurred from 1.0 with BORDER_REFLECT mirror tiles hidden by the blur peak (AE Motion Tile + mirror edges).
def pullback_out(t, d, frames=8): u = ramp(t, d-fr(frames), d, 'expo_in'); return 1+.35*(1-u), 0, 0, 0, u
def pullback_in(t, d, frames=10): u = ramp(t, 0, fr(frames), 'expo_out'); return 1+.35*u, 0, 0, 0, 1-u
# 9 ROLL-ZOOM (spin zoom transition): crash zoom + 20..30 deg roll over 7 frames, reversed on the incoming shot.
def rollzoom_out(t, d, frames=7): u = ramp(t, d-fr(frames), d, 'expo_in'); return 1+.6*u, 25*u, 0, 0, u
def rollzoom_in(t, d, frames=10): u = ramp(t, 0, fr(frames), 'expo_out'); return 1+.6*(1-u), -25*(1-u), 0, 0, 1-u
# 10 SPEED-RAMP ZOOM: pair a punch with a 60 fps speed ramp (1x -> 0.4x on the feature, back to 1x); time-remap helper:
def ramp_time(t, a, b, slow=.4):   # source time for output time t; 1x until a, eases to `slow` until b, back to 1x
    if t <= a: return t
    seg = min(t, b)-a; k = 1-(1-slow)*E['io'](min(seg/max(b-a, 1e-6), 1)); st = a+seg*(1+k)/2
    return st+(t-b if t > b else 0)
# 11 IMPACT SHAKE (only with a punch/crash hit, never alone): 3-6 px, 5-8 frames, decaying.
def shake(t, at, px=5, frames=7):
    if not (at <= t < at+fr(frames)): return 0, 0
    k = 1-(t-at)/fr(frames); return px*k*math.sin(t*97), px*k*math.cos(t*71)
def compose(*moves):   # multiply zooms, add roll/offsets, max blur
    def f(t, d):
        z, r, x, y, b = 1, 0, 0, 0, 0
        for m in moves:
            mz, mr, mx, my, mb = m(t, d); z *= mz; r += mr; x += mx; y += my; b = max(b, mb)
        return z, r, x, y, b
    return f

def warp(frame, z, rot, cx, cy, dx=0, dy=0, W=1080, H=1920):
    """Zoom/rotate around the ANCHOR (cx,cy) = the product/feature point, placed back at the same screen spot."""
    M = cv2.getRotationMatrix2D((cx, cy), rot, z); M[0, 2] += dx; M[1, 2] += dy
    return cv2.warpAffine(frame, M, (W, H), flags=cv2.INTER_LINEAR, borderMode=cv2.BORDER_REFLECT)

def zoom_blur(img, strength, cx, cy, n=7, spread=.10):
    """Radial (zoom) blur = AE CC Radial Fast Blur / Premiere Transform shutter / CapCut 'Zoom lens' blur.
    Average n scaled copies around the anchor; spread 0.06-0.14 at strength 1."""
    if strength < .03: return img
    acc = np.zeros(img.shape, np.float32); s = spread*strength
    for i in range(n):
        k = 1+s*(i/(n-1)); M = cv2.getRotationMatrix2D((cx, cy), 0, k)
        acc += cv2.warpAffine(img, M, (img.shape[1], img.shape[0]), borderMode=cv2.BORDER_REFLECT)
    return (acc/n).astype(img.dtype)
```

## VO SYNC (after the user sends the voice)

1. Segment: 16 kHz mono, 10 ms RMS, threshold ~0.01, merge gaps <= 0.18 s.
2. Transcribe EVERY segment with Offline Thai ASR. TTS merges lines, splits at commas and may drop a line (check the CTA).
3. Map script lines to segments by numbers, English terms and key words. To split a merged segment, find the energy dips (20 ms envelope, minima < 35% of max), transcribe each side, and split where the left side ends with the first line's last word.
4. Build the VO: cut pieces [a-0.08, b+0.05], inner gaps capped at 0.20 s, 0.08 s between lines. A line shorter than ~1.2 s merges with the next scene. Scene boundary = next line start - 0.15 s. One phrase-time table drives the scene lengths, text, SFX and flashes; patch plan/SFX/mix from that table only.
5. Re-time or slow scenes to the spoken beats (the clip may grow, but never past 40 s). If the VO runs over 40 s, tighten the gaps (0.08 s between lines) and use `atempo` <= 1.12. If it is still over 40 s, tell the user which lines to cut rather than speeding it up more. If it is under 15 s, ask for one more spec line.
6. Final check: transcribe each scene window of the finished video and confirm its line is there.

### foley.py: harvest real sounds from the source clips
- Probe every clip's audio first. Run ASR on 5 s windows. If speech or music dominates (ASR returns words, or high onset density with no silence), that clip's audio is narration/music, not foley; only use its gaps.
- Onset detection: 10 ms RMS in dB. An onset is a local peak at least 6 dB above the 300 ms running median and no more than 45 dB below the clip maximum. Keep at least 120 ms between onsets.
- Cut each candidate from -20 ms to the point where the level falls 20 dB, max 0.6 s; for a slide or rustle, max 1.2 s.
- Measure each candidate:
  - SNR: the peak compared with the 200 ms before it.
  - Duration and spectral centroid.
  - Type: click < 80 ms, thock 80-200 ms, slide/rustle > 300 ms.
- Keep only clean candidates: SNR at least 12 dB and no speech (ASR on the slice returns nothing).
- Write a table: clip, time, type, SNR, centroid. Look at a frame for each kept candidate to name the action (e.g. "key press, A 39.4 s").
- Processing: `highpass=f=80`, `afftdn=nr=10` only if hiss is audible in the numbers (noise floor > -50 dB), and a gentle `lowpass=f=12000`. Keep the natural air; don't dull a real click to 2-4 kHz. Use a 5 ms fade-in, a 40-80 ms fade-out, and a peak of 0.12-0.20.

```python
# foley.py - list clean, real product sounds in a clip's own audio (no synthesis)
import numpy as np, subprocess, sys
SR = 48000
def load(p): return np.frombuffer(subprocess.run(f"ffmpeg -v 0 -i '{p}' -ac 1 -ar {SR} -f s16le -", shell=True, capture_output=True).stdout, np.int16) / 32768
def scan(p, min_snr=12):
    x = load(p); hop = SR // 100
    r = np.sqrt(np.convolve(x**2, np.ones(hop) / hop, 'same'))[::hop]; db = 20 * np.log10(r + 1e-9)
    med = np.array([np.median(db[max(0, i - 15):i + 15]) for i in range(len(db))]); top = db.max(); out = []; last = -99
    for i in range(1, len(db) - 1):
        if db[i] >= db[i - 1] and db[i] >= db[i + 1] and db[i] - med[i] > 6 and db[i] > top - 45 and i - last >= 12:
            pre = db[max(0, i - 20):i - 2].mean() if i > 3 else db[i] - 60; snr = db[i] - pre
            j = i
            while j < len(db) - 1 and db[j] > db[i] - 20 and j - i < 120: j += 1
            a, b = max(0, (i - 2) * hop), j * hop; seg = x[a:b]
            spec = np.abs(np.fft.rfft(seg * np.hanning(len(seg)))); fq = np.fft.rfftfreq(len(seg), 1 / SR)
            cen = float((spec * fq).sum() / (spec.sum() + 1e-9)); dur = (b - a) / SR
            kind = 'click' if dur < .08 else 'thock' if dur < .2 else 'slide/rustle' if dur > .3 else 'tap'
            if snr >= min_snr: out.append((round(i / 100, 2), round(dur, 3), kind, round(snr, 1), int(cen))); last = i
    return out
if __name__ == '__main__':
    for p in sys.argv[1:]:
        for t, d, k, s, c in scan(p): print(p, t, d, k, 'snr', s, 'centroid', c)
```

### Placement
- **Real sync first.** When the picture shows the action (a key pressed, the knob turned, a lid lifted), use the sound from the same clip at the same moment, aligned to the contact frame (the frame-difference peak). A sound must never play over a picture that contradicts it, e.g. typing sound over a still keyboard.
- **Production-sound bed.** On scenes where a clip's own audio is clean, keep it under the VO at -30 to -24 dB below the voice, with a 2-frame audio crossfade at each cut. This makes cuts feel real. Mute it where it holds speech or music.
- **Transitions.** By default a cut gets either nothing or one real action sound landing on the cut frame (a key thock, a case click). There are no swooshes unless they come from the user's files.
- **Hook opener.** Use a real sound on or near frame 0 (e.g. the first key thock, the box slide). Use a different opener from the last video. The retired synthetic openers are: thump (Soundcore R50i NC), shutter (AULA V9 Pro+), beep (Redmi Watch 5), mclick (Attack Shark R82 HE), shimmer (Edifier MP85), pop (FURYCUBE V68).
- **Budget per 15-40 s:** 1 opener, 3-6 real action accents on the key words/visual moments, at most 2 sounds on cuts, and the clean production bed where available.
  - Never use the same sample twice in one video. If a second similar hit is needed, take another take from the footage.
  - Never reuse a sample across consecutive videos for the same moment.
- **Levels:** SFX peak 0.10-0.20 before the master. Duck under the VO (`sfx*(1-0.6*env)`, envelope smoothed 60 ms twice). ## PRO CRITIC REVIEW (user rule 2026-11-02: every video gets a professional critic before delivery)

The user asked for a professional critic on every video ("เพิ่มนักวิจารณ์มืออาชีพมาหนึ่งคน"). The critic is a SEPARATE agent that has not seen the work being made, so the edit is not grading itself.

When: after your own QC passes, before delivery. Order: build -> own QC -> critic -> apply fixes -> re-check the fixed scenes -> deliver.

How:
1. Render review material: the video plus per-scene review strips (7 frames per scene at 0.1/0.35/0.6/0.9/1.3/1.8 s and the last frame, labelled "scene t"; 3 scenes per image).
2. Spawn ONE critic with the Agent tool (subagent_type general-purpose, run_in_background false). Brief it as: senior motion-graphics director + TikTok product-ad critic, 10+ years, harsh, specific, practical. Give it the file paths, the scene timeline (name, start, length) and the constraints it must respect: the standing user rules (source captions untouched, white/yellow text with outline and no box, voice first with minimal on-screen words, no particles, no third-party characters, verified specs not to be questioned, user-requested elements to leave alone). It may extract extra frames with ffmpeg.
3. Ask for: a score /10 for graphic quality and for meaning/clarity; the 8-12 most important fixes, prioritised, each with scene + time, what is wrong, and the exact fix (position/size/timing/easing values). Focus: too much on-screen text (flag any scene over ~6 words or text that repeats the VO; the user wants voice first), legibility at phone size, collisions/clipping, graphics or text covering the product, graphics landing late (fully resolved by ~0.9 s, readable >= 1.2 s before the cut), hierarchy, one consistent line/glow style, anything amateur. Never suggest adding explanation text. Under 600 words.
4. Apply every fix that doesn't break a user rule. If a fix conflicts with a rule, skip it and say why. Re-render and check the touched scenes on frames.
5. In the delivery message: the critic's score, the fixes applied (short list), and anything skipped.

Lessons from the first critic run (Attack Shark X11, scored 5.5/10 before fixes):
- Graphics must be fully drawn by ~0.9 s into the scene; build-ons in 0.5-0.6 s (expo-out), multi-part staggers 0.06-0.1 s.
- Graphics must MEAN something AND look rich: keep the effects (snap arcs, scan beam, reticle, odometer, glow) and tie each one to the spec it shows. Removing the effects made it "จืด" (bland); spectacle without meaning is rejected ("ความหมายน้อย อย่าใส่มั่ว"). The meaning comes from the graphic's form + the VO, NOT from extra explanation text: a graphic carries at most one tiny value label ("90°", "40 มม.", "1 ms"); no explanation sentences on screen (user 2026-11-03: too cluttered).
- Odometer digits are masked to one cell per column; separators fixed from frame 1; counted titles must never show a wrong spec mid-count (no counter on a title that a paused frame could misread).
- Keep graphics off the product and off source captions; highlights must follow the footage (e.g. the 2.4G icon lit on the 2.4G shot, the cable icon on the cable shot).
- Labels on phone: value labels ~44-64 px; never cut at the frame edge.
